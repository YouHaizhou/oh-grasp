# 几何与路由

**要解决的核心问题**：图算法给出的是「谁在第几层、层内排第几」，只是**顺序**。要画出来还需要把它变成**坐标**：每层的 y、每行的 x、盒子多大、连线怎么弯、标签放哪、多个区域怎么堆。

## 常量表

| 常量 | 值 | 含义 |
|---|---|---|
| `CW` / `CH` | 236 / 78 | leaf 盒宽 / 高（内容恒定：名字 + ≤2 行描述） |
| `GW` / `GH` | 282 / 96 | group 盒宽 / 高（上下要留端口位） |
| `HGAP` | 44 | 同行盒子之间的横距 |
| `VGAP` | 62 | 层与层之间的纵距（要留出连线通道） |
| `PAD_LR` / `PAD_TOP` | 44 / 18 | 画布左右 / 顶部留白 |
| `REGION_GAP` | 40 | 两个弱连通分量之间 / 分量与网格带之间的间距 |
| `GRID_CAP` | 940 | 网格带每行宽度上限 |
| 反馈通道 `lane` | 170 | 右侧留给反馈弧的宽度（**仅在有反馈边时产生**） |
| `gx` | `Wc + 26` | 反馈弧竖走段的 x 坐标 |

尺寸都写成常量而不是从内容算——因为内容被 `fitWidth`/`wrap2` 裁到固定行数，盒高因此恒定。盒高恒定带来的好处：行几何、错位、重叠全变成简单算术。

## 1. 三次贝塞尔前向边

**问题**：层间的连线。直线当然可以，但两条从同一出口上下分叉的线会重叠成一团，且读者无法判断线在哪一条上行。

**做法**：三次贝塞尔，控制点选在**两端 x 上、纵向中点 y 上**

```
M x1 y1  C x1 my  x2 my  x2 y2     my = (y1 + y2) / 2
```

效果：从源盒底边**竖直出发**、到目标盒顶边**竖直到达**，中间平滑过渡。竖直的出入段让「哪条线接在哪个端口上」一目了然——这正是端口为中心的节点盒（ADR-0006）要的读法。

**为什么不用直线**：直线接入盒顶时是斜的，斜线在端口圆点附近会挤成一片，箭头方向也不明确。

**位置**：viewer.js:338。

## 2. 反馈弧复合路径

**问题**：后向边（回边）不能按前向边画——它的目标是**更上层**的盒子，直接连上去会向上折返、穿过中间所有层。语义上它是「反馈」，应该一眼看出与主线不同。

**做法**：复合路径走**右侧专用通道**

```
贝塞尔出（从源盒底，向右拐到通道 x）
→ 直线竖走（在 x = gx 上，从源下方一直到目标上方）
→ 贝塞尔入（从通道拐回目标盒顶）
```

三段拼接：`C … ` → `L gx y` → `C …`。视觉上：橙色（`#f59e0b`）、虚线（`5 3`）、独立箭头 marker（橙色）、标签带 `↺` 前缀、右对齐贴在通道内。

**为什么走右侧而不是绕过上方/下方**：右侧是唯一还没被占用的方向（上方有层 0、下方有最深层、左侧留给可能的对称扩展）。且侧栏位置本身成了**语义信号**——「在侧栏上跑的一定是回边」（ADR-0008 把这条升级成了硬规则：侧栏只服务反馈边）。

**通道宽度只在有反馈边时产生**（`lane = back.length ? 170 : 0`）——没有回边的图不该多出 170px 空白。

**位置**：viewer.js:344。

## 3. 行几何（层高 + 行内居中）

**问题**：同一层里可能混排 group（高 96）和 leaf（高 78）。层高取小了盒子会溢出到下一层；取大了白白浪费。

**做法**：
- 层高 = 该层**最高**节点的盒高（`rowH[L] = max(sizes[id].h)`）。
- 层与层之间固定再加 `VGAP`。
- 行内水平：先算全图最宽行宽 `Wc`，每行按自己的实际宽度在 `Wc` 内居中（`x = (Wc - rowW) / 2`）。

**为什么取 max 而不是各层独立堆**：层是全局横向带，一层里的盒子必须在同一个 y 顶部对齐——不然读者无法一眼判断「这两个是同一层的」。

**为什么居中而不是左对齐**：分层图天然是中间宽两头窄的菱形（第一层和最后一层通常只有一两个盒子）。左对齐会让菱形歪向一边、左侧留白巨大，正是用户反馈里的「左右侧空白」问题的一个来源。

**位置**：viewer.js:226。

## 4. 区域堆叠 + 尾随网格带

**问题**：多个弱连通分量各自跑完布局后，坐标都是**从 0 开始**的局部坐标。直接拼到一起会全部叠在原点。

**做法**：纵向游标 `cursor` 从 `PAD_TOP` 开始，每片布局完就 `cursor += g.H + REGION_GAP`；每个分量整体包一层

```html
<g transform="translate(0, g.top)"> … 该片全部内容 … </g>
```

**坐标系隔离**是这里的关键设计：片内所有几何计算（`flowGeometry`、边路径、标签位置）都用局部坐标，**不需要知道自己在全局的哪个位置**。全局位置只在最后套一层 `translate`。这消除了「每个函数都要带一个 y 偏移参数」的传染。

**曾经的 bug**：早期版本把 `g.top` 加进了坐标计算，但 SVG 没有套 `translate`——结果所有分量画在同一位置重叠。修法是让**坐标系隔离彻底**：要么全用局部坐标 + 外层 translate（现在），要么全用全局坐标。混用必炸。

网格带同理，多一个横向居中：`translate((contentW - grid.W) / 2, grid.top)`。

**位置**：viewer.js:361。
**测试**：`oh-grasp/fortest/smoke-viewer.js` —「多弱连通分量堆叠为纵向独立 translate 区（不重叠）」（断言 ≥3 个 `translate` 且 y 各不相同、6 个节点各渲染一次）。

## 5. 白描边文字（`paint-order: stroke`）

**问题**：边标签压在两盒之间的连线上。普通文字会被线穿过，读不清——这正是用户反馈「连线上的字看不懂」的一部分（另一半是文字内容本身，见 ADR-0008 双语）。

**做法**：给文字一份**白色描边**（`stroke: #ffffff; stroke-width: 4`）并把绘制顺序改成「先描边后填充」（`paint-order: stroke`）。描边在文字周围形成一圈白底，把底下的连线「擦掉」。

**为什么不用 `<rect>` 垫底**：需要先量文字宽高才能画矩形，而宽度是估算的（见 text.md），估算误差会露出黑边或白边。`paint-order` 由渲染器按**实际字形**描边，零误差，且不增加 DOM 节点。

**位置**：viewer.js:354。

## 6. SVG marker 箭头

**问题**：每条边要有箭头指示方向。

**做法**：`<marker>` 定义 + `marker-end` 引用，`orient="auto"` 让箭头随路径**切线方向**自动转向。每个方向一种颜色，marker id 由递增计数器 `markerSeq` 生成（避免同一 SVG 内 id 冲突）。

**为什么不用手工画三角形**：手工画要自己算切线角度（贝塞尔端点的切线是控制点连线方向），且箭头位置要留出路径缩短量。`marker` 是 SVG 原生能力，`refX` 负责把箭尖对齐到路径终点。

**位置**：viewer.js:332。

## 7. 节点盒（`nodeSvg`）

**问题**：一个盒子里要放：类型标签（GROUP / INTERNAL）、名字、≤2 行描述、以及 group 才有的上下端口。

**做法**：纯字符串拼 SVG。纵向基线固定：类型标签 y+18、名字 y+34、描述两行 y+53 / y+69。名字用 `fitWidth`（截断，不折行），描述用 `wrap2`（折行，最多两行）。

**端口**画在盒宽中点、上下边缘上（`cx = x + w/2`, `cy = y` / `y + h`），半径 6，`class="port"` 供事件绑定。**空方向不画端口**（ADR-0006）——没有入边的 group 没有上方圆点，读起来是「无组间边」而不是「无输入」；这一步由 `counts[id].in/out` 为 0 时跳过渲染实现。

**位置**：viewer.js:295。

**待改**（ADR-0008）：端口候选「代表内容」文字、空方向显式「—」、`×N` 改口径为不同内容种数。
