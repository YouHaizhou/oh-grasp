🧩 **Q2** - **旧 IR 留不留一份作结构对照**
既然结构是重新推导的，新旧之间会有结构差异（模块增减、连接增减、分组边界移动）。
- (a) 覆盖旧的，不留。
- (b) 旧的重命名留一份（如 `oh-grasp-ir.v1.json`），配一份**结构 diff**（模块增减 / 连接增减 / 分组成员变化）。

💡 推荐 (c)。你要的是**知道变了什么**，不是**留着旧的**——旧的 IR 没有长期价值（它是模型的一次输出，不是事实源；事实源是 `archify.mjs`）。留文件会让 `generated/` 里躺着两份看着都像真的产物，将来分不清哪份是当前的。(c) 把价值（diff 报告）留下、把包袱（第二份 IR）丢掉。若你想自己 diff，选 (b)。

👀 **Q3** - **清单里列出的 connection，能不能点开看四段**
四段说明的主要可点处现在是**画布上的边**。但 connection 还会出现在三个清单里：端口弹窗（最多 12 行）、group 弹窗的「边界数据流」（每行是 `成员 → 内容 → 对方成员`）、聚合边弹窗里按来源分组的清单。在这些清单里，画布上的那条边往往**够不着**（子图里被缩放、顶层被折叠成聚合边——清单里的原子 connection 在顶层根本没有对应的可见边）。
- (a) 清单行**可点**，用统一弹窗**替换**当前内容；关闭即回到画布。
- (b) 清单行**可点**，弹窗维护**一层返回**（显示 `← 返回 参数解析`）；回到底层才真正关闭。
- (c) 清单行**不可点**（只读列表）；四段只在画布上点边才看得到。

💡 推荐 (b)。(a) 的坑是**丢失位置**：从 group 弹窗点进一条 connection 的四段，关掉之后 group 弹窗也没了，读者得重新找回来——12 行的清单里这很烦。(c) 则让四段在「聚合边弹窗」这个场景下**根本看不到**（那里的原子 connection 在画布上没有可见的边），而你反馈 2 要的正是「点开看它从哪来、经过什么、输出什么、用于什么」。一层返回的代价很小：统一弹窗多一个可选的面包屑槽位。

ans：b。
