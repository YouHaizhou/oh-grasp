 ⚠️  Q1 - source 校验的严格度
  source 现在必填非空（硬失败）。升级成「完整函数体」后，要不要把「必须与源文件子串一致」也做成硬失败？
  - (a) 硬失败：非空 + 白空格归一后子串匹配，否则报错让模型重试。跟现有「非空必填」的严格度一致。
  - (b) 软警告：非空仍硬失败，但「非子串」只警告不阻断——容忍模型轻微改写，牺牲一点防编造。
  - (c) 硬失败 + 白空格归一：同 (a)，但明确把「归一化」写进校验（我倾向的落法）。
  💡 推荐 (c)。子串匹配前先把连续空白压成单空格再比对，既拦住胡编、又不被缩进/换行差异误伤；归一是「宽松」的具体实现，值得写死成规则。风险：若模型原文摘取仍偶
  发改写，会让 pipeline 多绕几轮——真遇到再降级成 (b)。
ans:c.

  🧩 Q2 - sourceLine 必填还是可选
  行号只展示不校验，值错就是「显示错的行号」。
  - (a) 可选 int：模型给了就显示「第 N 行」，没给就不显示。
  - (b) 必填 int：schema 强制，缺了报错（但不验值）。
  - (c) 必填 + 轻校验：sourceLine 附近确实能找到 label。

  💡 推荐 (a)。它是纯展示字段，强制必填只加摩擦不加价值；错的比没有更糟，可选让弱模型干脆不给。
