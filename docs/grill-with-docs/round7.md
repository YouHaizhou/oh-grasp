 👀 Q1 - fit 之后的可读性
  4640px 的图 fit 进 ~1060px 视口，缩放系数约 0.2，节点文字会缩到 3px——全可见，但不可读。
  - (a) 可接受：初始 fit 全图，用户滚轮放大细看（这正是缩放/平移存在的意义）。
  - (b) 设最小缩放下限（如 0.4），大图初始只 fit 宽度、允许横向滚动。
  - (c) 初始 100% 可读，另加一个「Fit」按钮一键看全貌。
  💡 推荐 (a)。fit 只是初始态，不是终态；双击复位我打算改成「回到 fit 态」而非硬回 100%，这样「看全貌↔看细节」两个锚点都有。
ans：a。

  ⚠️  Q2 - source 的「与源文件一致」怎么验
  完整函数体要靠模型从源文件原文摘出，但模型会截断/加省略号/悄悄改写。校验怎么拦编造又不误伤？
  - (a) 子串匹配：source 去首尾空白后必须原样出现在源文件里。宽松，容忍行号/空白的小误差。
  - (b) 行号锚定：source 必须从声明的起始行开始、与该行起原文一致。严格，但模型报错行号就误报。
  - (c) 两者都要。
  💡 推荐 (a)。目标是「防编造」不是「逐字节校验」；子串已能拦住胡编的源码，行号只当展示用、不做校验依据——这也能反过来降低对模型行号准确度的依赖。
ans：a。

  🧩 Q3 - IR 契约里 source 相关字段怎么落
  - (a) 新增 sourceLine（int，起始行号，展示用），source 语义改为「完整函数体（原文）」。
  - (b) 只改 source 语义为完整函数体，不加行号（弹窗就不显示「第 N 行」）。
  - (c) 加 sourceLine + sourceEndLine 行范围。
  💡 推荐 (a)。一个起始行号够定位 + 展示，EndLine 冗余；行号只在弹窗里标「第 N 行」，不参与校验。
ans：a。
