## 诊断（facts，我的活）

已核对真实 IR（47 条 connection / 8 个 group），几条关键事实：

1. **连线穿盒是真的**。顶层单一弱连通分量分 4 层：L0 `[cli_core, arg_parse]`、L1 `[misc_commands, compare, validate_migrate]`、L2 `[render]`、L3 `[diag, artifact]`。跨层 ≥2 的前向边有 **4 条**（`arg_parse→render`、`cli_core→render`、`validate_migrate→diag`、`validate_migrate→artifact`），它们的贝塞尔控制点落在两盒中点，曲线正好穿过中间层的盒子。另有 1 条反馈边（`render→cli_core`），走右侧通道，不穿盒。
2. **箭头被挡是真的**。入边终点画在 `y = 盒子顶边`，而盒子（含端口圆点）**后画**，把箭尖盖住。
3. **47 条 connection label 全是英文**（`renderer script path`、`renderer + args`、`subprocess result`…），而所有 `description` / `detail` / `meta.input` / `meta.output` / 分组描述**都是中文**。所以「双语」的缺口，主要缺口在这 47 条 label 上——中文不是新增一种语言，而是补上本来就没写的中文。IR 里没有 `connection.description` 字段，viewer 只渲染 `c.label`。
4. **`×N` 数的是「连接条数」，不是「不同内容数」**。`grp_artifact` 入端口 ×4，其实 4 条边同一个内容 `artifact buffer`；`grp_arg_parse` 出端口 ×12，只有 4 种不同内容；`grp_cli_core` 入 ×12 对应 8 个来源 / 6 种内容。数字与「里面看到的内容种数」对不上，就是你反馈 6 的第一半。
5. **反馈 6 的第二半：空方向的端口被我隐藏了**（ADR-0006「不显示空端口」）。于是 `grp_arg_parse` 没有入端口、`grp_diag` / `grp_artifact` 没有出端口——图上读起来是「无输入 / 无输出」，可它们的成员内部明明在消费 `process.argv`、产出 artifact。**画布上的 ×N 与弹窗里的边界边数字其实完全一致**，误导来自「隐藏 = 读成没有」＋「计数口径是连接数」这两件事。
6. **头部 `meta.input` / `meta.output` 是手写中文散文**（3 条文件级），IR 里没有任何字段把它绑定到某个 group/module 端口，与推导出的 I/O 是两套东西。
7. **B 视图没有任何 ADR / round 决策背书**，它来自最初的 spec（story 19，commit `0c10924`）。删它不 supersede 任何 ADR，但 spec 那条要注明作废。

⚖️ **Q1** - **长边穿盒与交叉怎么修**（反馈 1）
一条边跨越 ≥2 层时，曲线会穿过中间层的盒子（事实 1 的 4 条）。三条路：
- (a) 引入**虚节点**：长边在每一层间切成短直段，从相邻盒子的空隙里穿下去（Sugiyama 经典做法，对任意输入成立）。
- (b) 跨度 ≥2 的边走**右侧通道**（与反馈弧同族），绕开盒体但会拉长、增加外圈。
- (c) 只调曲线形状，不动拓扑（治标）。
💡 推荐 (a)。它一次解决「穿盒」和大部分「交叉」，且是通用算法；(b) 留作跨度 ≥3 时的兜底频道。
ans：a。

👀 **Q2** - **箭头被端口/盒体遮挡**（反馈 5）
入边终点落在 `y = 盒子顶边`，盒体与端口圆点后画，盖住箭尖。
- (a) 入边终点**外移到端口外缘上方约 8px**，反馈弧入端同样处理。
- (b) 边与箭头改到**节点之上**绘制（箭头压盒）。
- (c) 端口圆点画在盒体之下。
💡 推荐 (a)。纯几何修正，不动布局算法，也不改变「节点盖住边端点」这一稳定层序。
ans：a。


🏷️ **Q3** - **连线中点默认显示什么**（反馈 2、4）
现在中点显示模型写的原始 label（`renderer script path`），脱离源码看不懂。
- (a) 中点只放**一句中文动宾短语**（如「传入渲染器路径」）；**点这条边**弹出四段：**来源 → 处理 → 输出 → 用途**。
- (b) 中点保留数据名，四段说明只放在悬停。
- (c) 中点两行：动作 + 数据名。
💡 推荐 (a)。你要的「从哪来、经过什么、输出什么、用于什么」是**边的详情**，塞中点必糊；中点给一句能秒懂的短语，细节点开看。这同时定了 IR 要新增 `connection.description`（四段）。
ans：a。

🎯 **Q4** - **中英双语怎么交付**（反馈 3）

- (c) 只双语 UI 外壳（「依赖 Dependencies」这类），模型内容保持单语。

🧩 **Q7** - **端口口径：`×N` 数什么、空方向怎么表达**（反馈 6 的一半，事实 4+5）
