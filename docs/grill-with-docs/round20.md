🏷️ **Q2** - **`runtime` 里的值怎么写**
它是自由字符串数组（round18 Q4a），但自由到不统一就会碎：同一个符号可能被写成 `process.exit` / `process.exit()` / `process.exit(1)` / `调用 process.exit 终止进程`——反向索引和去重全都对不上。
- (a) **只写属性路径、不带括号不带说明**：`["process.exit", "process.cwd", "process.env"]`。
- (b) 带括号的调用形式：`["process.exit()", "process.cwd()", "process.env"]`。
- (c) 允许自然语言描述：`["process.exit(1) 终止进程"]`。

💡 推荐 (a)。`process.exit` 与 `process.exit(1)` 是**同一个结构事实**（这个模块会终止进程），参数是细节不是结构；`process.env` 本身是属性不是调用，带括号（b）会写成 `process.env()` 这个不存在的调用形式。prompt 里给一句「写属性路径，不带参数」就能统一，validate 顺手加一条正则（`^[A-Za-z_$][\w$]*(\.[A-Za-z_$][\w$]*)+$`）就能拦住写歪的——这条比 `uses` 还严，但值得，因为它是唯一的自由文本字段。

ans：a。

👀 **Q4** - **端口的「代表内容」放在哪**（round17 Q7 的推论）
你定了端口的 ×N 从「连接条数」改成「不同内容种数」，并在**端口旁给代表内容**。问题是放哪儿——现在端口圆点画在盒宽中点、上下边缘上，`×N` 贴在圆点右侧**盒内**（`y+7` / `y+h-6`），而盒内纵向已经被 类型标签 / 名字 / 描述两行占满（`GH=96`）。
- (a) **盒内、紧跟 ×N 右侧**：`×3 质量档`，可用宽度约 130px（font 10 下约 13 个中文字），用 `fitWidth` 截断。盒高不变。
- (b) **盒外、端口圆点旁**（入端口标在盒上方、出端口标在盒下方）：不挤盒内，但那片空间正是连线与标签走的地方（`VGAP=62` 的通道）。
- (c) **盒内另起一行**（描述压成一行，腾出位置）：`GH` 从 96 涨到约 114，每层的行距跟着变大，整张图变高。

💡 推荐 (a)。盒高不变意味着**布局算法的输入不变**——行几何、层距、区域堆叠全都不用动，改动被限制在 `nodeSvg` 一个函数里。(b) 把新文字放进连线通道，是拿「读得清」换「盒内宽松」，而连线通道是整张图最拥挤的地方。(c) 让每个 group 盒都长高 18px，为了一个次要信息付全局代价。
