 Q1 — 概览图里到底画什么

  「代码/项目 → 结构概览图」定了输入输出，但图的内容还有几个轴，这决定增强的价值点在哪：
  - (a) 目录/文件结构树：项目有哪些文件和目录、怎么组织——但这是 agent 本来就会的活（ls/tree），增强价值低；
  - (b) 模块/组件 + 依赖关系：哪些模块、谁 import 谁、依赖方向——agent 不靠引导做不准，增强价值高；
  - (c) 架构分层：前端/后端/DB/服务等高层架构视角；
  - (d) 组合：结构树打底 + 依赖/分层关系叠加。
ans：c目前已经有项目做了，我想做的是针对单代码文件生图，这个文件依赖哪些外部模块，内部有哪些模块，以什么样的方式组合,输入，输出是什么，文件作用是什么。

  🧩 Q2 — 校验脚本具体校验什么

  给定输出是 Mermaid，校验脚本能做的检查，从易到难：
  - (a) 语法合法：Mermaid 能 parse，不报语法错；
  - (b) 结构约定：节点命名规范、图连通、无孤立节点、层级一致、每个模块有描述；
  - (c) 与代码事实一致：图里每个模块在磁盘上真有对应文件/目录（脚本 fs 遍历比对即可）、依赖方向正确。
ans：按推荐来
  💡 推荐 (a)+(b) 全做 + (c) 里的「存在性」检查：前两者是确定性、标准库能干的；「图里说的模块真存在」这一条也能靠 fs
  遍历硬校验，价值极高（防模型编造模块）。至于「依赖方向是否正确」这种语义判断，脚本查不了，交给 prompt 里的指令去约束。
