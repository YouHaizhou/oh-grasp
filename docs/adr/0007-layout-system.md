# 排版系统通用化：端口为中心的节点盒 + 断环分层宏布局

对「给模块/分组做分组」上线后的 5 个反馈（I/O 判断错、排版没设计好、子图无整体操作、group 概览 badge 重复 / 数据流看不懂、边注释不清）做第二轮渲染。本轮把排版从「修这张卡」抬成「对任意同构输入都成立的通用方案」，分**节点盒**与**画布宏布局**两层。

## 节点盒：端口为中心，盒内只留「身份 + 作用」

I/O 已从「一句话摘要」变为「从边推导的列表」（ADR-0006），N 条边塞不进任何固定盒子——所以 I/O 的表达**交给端口，不进盒体**：

- 盒体 = 名字 1 行 + description ≤2 行（超长省略号，全文进弹窗）。盒高因此基本恒定，content 多长都不挤。
- 上/下端口各是一个点，旁标「×N」（入/出边条数），点击弹清单。N=0/1/50 盒体都不变。端口本就是「多边汇聚一点」的抽象（ADR-0005），天然为任意 N 而设。
- 端口旁标只用于**折叠单元**（group：内部边被隐藏，边界边条数是新信息）；叶子与子图成员的边是直接画出的，不重复标。
- 冗余的「GROUP · N 模块」徽标删除（它显示成员数、成员数相同即重复）。成员数只留在 group 弹窗头（`group · N 模块`）。

## 边注释：给具体内容，放中点加白晕

- 顶层聚合边（多条同向折叠成一条）的 label = 真实 label 逗号拼接（如 `renderer + args · renderer invocation`），超 3 条截「前 2 条 +N」。
- label 从起点挪到**边中点**、加白底晕圈，不再压在曲线上。
- prompt 侧顺带收紧：要求模型把每条 connection 的 label 写得短而具体（是「renderer + args」不是「数据」）。

## 子图：与顶层共用同一套交互与布局内核

- group 弹窗的子图复用顶层滚轮缩放（光标锚点）/拖拽平移/双击复位。
- 组内无边时**优雅降级**：退化为成员网格卡片（含各自 description），不强行画线、不编造（星形调用使多数组内真无边）。

## 画布宏布局：断环成 DAG + 反馈边绕侧 + 弱连通分量分块

任何输入图通用的三条规则：

1. **环不撒谎**：为分层先断环（DAG 化，方向全向下）；被断的闭合边画成**从输出端口绕侧边回到输入端口的外侧虚线弧**，标「↺ 反馈」。图主体干净向下，真实闭环仍全部可见可辨（不编造/不隐藏不变量不破）。
2. **排序压交叉**：层内顺序跑 barycenter 扫描（确定性，3~5 趟），而非插入序。
3. **孤岛分块**：按弱连通分量（图论事实、可校验）划分。主分量在前，其余每个分量各跑一套分层，收进**尾部独立区**（浅色分区），不再当「源头」混排误导读者。

非决策项一并落实：行距按层内最高节点 + 固定 gap 算（group 96 / leaf 78 混排不再空一大截）；顶层与 group 子图调**同一个**布局内核，行为一致。
