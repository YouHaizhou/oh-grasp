# 路由与端口：虚节点正交折线、侧栏只服务反馈边、端口口径

反馈第 1、5、6 条合起来是一次布局重做：

1. 「连线会穿过模块，产生交叉」——跨层 ≥2 的前向边是**贝塞尔曲线**，曲线中段直接压在中间层的盒体上；
2. 「连线的箭头会被 group 上输入、输入端点阻挡」——入边终点画在盒的**上边缘**，而后画的盒体/端口圆点把它盖住；
3. 「输入输出和具体内容对不上号，图上标明一个输入/无输入，具体里边有多个不同输入」——端口旁的 `×N` 数的是**连接条数**，而空方向被**整个隐藏**。

三条各自独立可推翻，但都是「这张图读不出来」的同一个现场，一起记。

## 长边：虚节点正交折线

跨层 ≥2 的前向边（`to.layer − from.layer ≥ 2`）不再走曲线，改为**正交折线**：

- 在每一对相邻层之间插一个**虚节点**（无实体、无形状、不渲染）；
- 虚节点的横向位置取该层上真实节点的**空隙**，线段逐层直角穿下；
- **虚节点参与 barycenter 排序**——它和其他节点一样进层内序列，占位、被重排。

**允许边与边交叉，只保证不穿盒体。** 交叉是能忍的（读者能顺着线走），穿盒是忍不了的（盒体是不透明矩形，穿过等于断线）。

可选方案里被否掉的两条：

- **绕顶部/底部的大弧**：线长翻倍，且多条长边绕同一侧时会在图外挤成一束。
- **在中间层找空隙一次跳过去**（直线穿两层）：得先知道「哪一列从头到尾是空的」，而层内顺序正是这轮要重算的东西——循环依赖。

## 侧栏只服务反馈边

右起那条 170px 的通道**只放回边**（back edge / 反馈边）。

考虑过让它兼任「长前向边的旁路」——长边绕出画布再从右侧回来。否掉的理由是**语义降级**：侧栏现在是一个语义信号（「在右侧 = 数据回流」），一旦同时装回边与长前向边，它就退化成「拥堵分流道」，读者再也不能靠位置判断方向。虚节点折线（上一条）已经把长前向边的问题在画布内解决了。

## 入边端点外移 ~8px

入边终点从盒的**上边缘**移到端口圆点外缘上方约 8px；反馈弧的入端同样处理。

**不动层序**（节点仍然盖住边端点）——这是刻意的：把边改到节点之下是更彻底的修法，但它要重排整个 SVG 的绘制顺序与区域变换，收益只是让「被盖住」变成「没被盖住」，而外移 8px 已经让箭头落在端口正上方可见。**代价**：箭头与端口之间多出 8px 空隙，靠端口圆点的半径填补视觉连续性。

## 端口口径：`×N` = 内容种数

| | 原来 | 现在 |
|---|---|---|
| `×N` 数什么 | 入/出**连接条数** | 不同**内容种数**（去重后计数） |
| 代表内容 | 无 | 取 IR 顺序第一条，画在 `×N` 右侧 |
| 空方向 | 端口整个隐藏 | 显式标「—」 |

**去重按 `zh` 文本**（不是按 label id、不是按 en 文本）：同一个内容在两处写出的 label 字符串可能不同，但 `zh` 是判定「是不是一回事」的锚点；按 `zh` 去重还有个副作用好处——**切换语言时数字不变**。若按当前显示语言去重，切到英文会让 `×12` 变成 `×9`，读者会以为结构变了。

`grp_arg_parse` 的出端口从 `×12` 降到 `×4` 就是这条的收益：12 条连接里其实只有 4 种内容。

**代表内容放盒内、紧跟 `×N` 右侧**：约 130px 可用宽（`GH=96` 的盒内纵向已被类型标签 / 名字 / 两行描述占满），用 `fitWidth` 截断。**盒高不变**是这条的关键——行几何、层距、区域堆叠全都不用动，改动被限制在 `nodeSvg` 一个函数里。

考虑过放盒外端口圆点旁（不挤盒内），否掉：那片空间正是 `VGAP=62` 的连线通道，是整张图最拥挤的地方。考虑过盒内另起一行，否掉：`GH` 要涨到约 114，每个 group 盒都长高，为了一个次要信息付全局代价。

**空方向不隐藏，显式标「—」**：`无输入` 和 `这个端口没画出来` 是两件事，读者分不清就会以为图漏画了。

## 代价与已知限制

- 虚节点让**边数不再等于几何单元数**——`countPorts` / `aggregateEdges` / `edgeLabel` 这些按连接计数的函数要各自确认一遍「数的是连接还是段」。
- 布局算法的输入变宽（层内序列里混进了虚节点），barycenter 的迭代次数可能上升；`graph.md` 里记的那条 O(V·E·passes) 隐患会因此更明显。
